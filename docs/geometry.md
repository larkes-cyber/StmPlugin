# `agent/geometry.py` — анализ геометрии модели

`geometry.py` — наш модуль. Он смотрит на 3D-модель «глазами технолога»: размеры, объём, замкнута ли
сетка, где нависания и сколько понадобится поддержек, похожа ли деталь на тело вращения (кандидат
на 5D). Он же перебирает ориентации модели и выбирает ту, где поддержек меньше всего.

- Используется только **numpy**, без внешних библиотек: модуль работает внутри Python 3.5 слайсера.
- С API слайсера модуль **не общается**. На вход он получает массив треугольников, на выход отдаёт
  словари. Данные из сцены собирает [`slicer.py`](slicer.md), а результаты становятся
  инструментами агента `analyze_geometry`, `suggest_orientations`, `apply_orientation`.
- Поэтому модуль удобно проверять отдельно от слайсера: `dev/test_offline.py` гоняет его на
  сгенерированных моделях (L-кронштейн, труба).

---

## 1. Входные данные и система координат

**Треугольники** — массив numpy формы `(F, 3, 3)`: `F` треугольников по 3 вершины по 3 координаты, в мм.

**Система координат — стол, ось Z вверх.** В сцене STE ось Y смотрит вверх, поэтому перед
анализом координаты переводятся:

| Функция | Что делает |
|---|---|
| `scene_to_plate(points)` | сцена → стол: `(x, y, z)` → `(x, −z, y)` |
| `plate_to_scene_vector(v)` | обратно, для осей поворота: `(x, y, z)` → `(x, z, −y)` |

Обе матрицы перехода — повороты (определитель +1), поэтому углы при пересчёте не меняются.

**«Вниз»** — вектор `DOWN = (0, 0, −1)`. Ориентация в модуле задаётся вектором `down`: это направление
*в текущих координатах модели*, которое после поворота должно смотреть на стол.

## 2. Базовые функции

### `face_data(tris)` → `(tris, normals, area)`
Для каждого треугольника считает нормаль (единичный вектор наружу, через векторное произведение)
и площадь. Вырожденные треугольники с нулевой площадью отбрасываются.

### `mesh_volume(tris)` → мм³
Объём замкнутой сетки как сумма объёмов тетраэдров «начало координат + треугольник»
(теорема о дивергенции). Берётся по модулю, поэтому не зависит от направления обхода.

### `mesh_topology(tris)` → `{watertight, open_edges, nonmanifold_edges}`
Проверка «герметичности» сетки:

1. Совпадающие вершины склеиваются (координаты округлены до 10⁻⁴ мм).
2. Для каждого ребра считается, сколько треугольников его используют.
3. В замкнутой сетке **каждое ребро ровно у двух треугольников**:
   - 1 треугольник — *открытое ребро* (дырка);
   - больше 2 — *неманифолдное* (самопересечения, «склеенные» тела).

На моделях больше 400 000 треугольников проверка пропускается (возвращается `None`), чтобы не тормозить.

## 3. Оценка одной ориентации — `evaluate_orientation`

Главная функция модуля. Для направления `down` и угла нависания `support_angle` она вычисляет:

| Поле | Смысл |
|---|---|
| `height_mm` | высота детали в этой ориентации |
| `bed_contact_mm2` | площадь, которой деталь лежит на столе |
| `overhang_area_mm2` | площадь граней, которым нужны поддержки |
| `support_volume_est_mm3` | **оценка объёма поддержек** |

Как считается:

```
               нормаль n
                   ↓        cos = n · down
        ┌──────────────┐    (1 — грань смотрит прямо вниз, 0 — вертикальная стенка)
        │   нависание  │
        └──────────────┘
          ↕ face_height      высота центра грани над столом
  ════════════════════════   стол
```

- **Глубина точки** — проекция на `down`. Самая «глубокая» точка — уровень стола.
- **Грань лежит на столе**, если она смотрит вниз почти строго (`cos > 0.985`, около 10°) и все её
  вершины не выше 0.05 мм. Такие грани дают `bed_contact_mm2`.
- **Грань — нависание**, если её угол от вертикали больше `support_angle`. Через нормаль это
  условие `cos > sin(support_angle)`. Грани на столе и у самого стола (ниже 0.1 мм) не считаются.
  Логика та же, что у настройки `support_angle` в слайсере: 0° — поддерживать всё, 90° — ничего.
- **Объём поддержек** — для каждого нависания: площадь проекции на стол (`площадь × cos`), умноженная
  на высоту над столом. Получается столбик от грани до стола.

> Это **оценка сверху**. Если под нависанием есть сама деталь, реальная поддержка короче. Для
> сравнения ориентаций между собой этого достаточно, а точное значение даст слайсинг.

## 4. Подбор ориентации — `suggest_orientations`

### Какие направления перебираются (`_candidate_directions`)

1. **6 направлений по осям:** ±X, ±Y, ±Z.
2. **Крупные плоские грани модели.** Нормали треугольников группируются (сетка с шагом 0.08) и
   сортируются по суммарной площади. Берутся 14 самых больших групп, и средняя нормаль каждой
   становится кандидатом. Если её направить вниз, модель ляжет на эту грань, а это самые
   естественные для печати положения.
3. Почти совпадающие направления (угол меньше ~3.6°) отбрасываются.

Обычно получается 10–20 кандидатов. Каждый оценивается функцией `evaluate_orientation`.

### Как выбирается лучшая (`_score`, меньше — лучше)

```
score = объём_поддержек / объём_детали            ← главное: меньше поддержек
      + 0.2 × высота / наибольший_габарит         ← ниже — быстрее и устойчивее
      − 0.3 × min(контакт / (5% площади), 1)      ← больше опора — меньше отрыв и коробление
      + 0.5, если контакт со столом < 25 мм²      ← штраф за неустойчивость
```

### Что возвращается

Реальный вывод для L-кронштейна из `dev/fake_slicer.py`. Он стоит «неудобно»: горизонтальная полка
висит в воздухе. Лучший вариант — положить его на бок:

```json
{
  "current": { …метрики текущей ориентации… },
  "support_angle": 50,
  "candidates": [
    {
      "rank": 1,
      "down": [0.0, 1.0, 0.0],
      "rotation": {"axis": [-1.0, 0.0, 0.0], "angle_deg": 90.0},
      "is_current": false,
      "metrics": {"height_mm": 40.0, "bed_contact_mm2": 1100.0, "overhang_area_mm2": 0.0, "support_volume_est_mm3": 0.0},
      "score": -0.1667,
      "support_change_vs_current_pct": -100.0
    }
  ],
  "note": "…ориентацию стоит выбирать и с учётом нагрузки…"
}
```

Score складывается так: поддержек нет (0) + 0.2 × 40/60 (высота) − 0.3 (контакт 1100 мм² — опора
максимальная) = −0.1667.

`support_change_vs_current_pct` показывает, насколько вариант лучше текущего положения, например
«−100 %» — поддержки не нужны совсем. Такие цифры агент приводит в объяснении.

> **Важно:** рейтинг учитывает поддержки, устойчивость и высоту, но **не знает о нагрузке**. Деталь
> слабее всего поперёк слоёв, поэтому для нагруженных деталей агент по промпту выбирает из первых
> вариантов тот, где слои не работают на отрыв, даже если он не первый в рейтинге.

### Поворот — `rotation_to_down(down)`
Возвращает ось и угол поворота, которые переводят `down` в `(0, 0, −1)`. Ось — векторное
произведение, угол — `atan2(|a × b|, a · b)`, это устойчиво и для малых углов. Особые случаи:
`down` уже смотрит вниз — поворот 0°; смотрит строго вверх — поворот на 180° вокруг X.
`slicer.apply_orientation` переводит ось в систему сцены и вызывает `RotateOperation`.

## 5. Тело вращения — `axisymmetry` (подсказка для 5D)

5D-режимы STE печатают на поворотной оси, и лучше всего подходят детали, похожие на тела вращения:
втулки, трубы, ролики, оболочки. Функция проверяет это так:

1. **Главные оси инерции.** По центрам треугольников (взвешенным по площади) строится ковариационная
   матрица, её собственные векторы — три кандидата в ось вращения.
2. Для каждой оси модель режется на **8 слоёв по высоте × 24 сектора по углу**, и в каждой ячейке
   берётся максимальный радиус от оси.
3. В каждом заполненном слое считается **разброс радиуса по углу** (коэффициент вариации
   `std / mean`). У идеального тела вращения радиус одинаковый во всех секторах, разброс ≈ 0.
   Слои, где заполнено меньше 75 % секторов, пропускаются: там не хватает вершин.
4. Выбирается ось с наименьшим разбросом (медиана по слоям).

| Поле | Смысл |
|---|---|
| `axis` | ось вращения (система стола) |
| `radial_cv` | разброс радиуса; **< 0.06 → `axisymmetric = true`** |
| `length_mm`, `max_radius_mm` | длина вдоль оси и наибольший радиус |
| `inner_radius_ratio` | внутренний радиус / внешний (медиана по слоям) |
| `hollow` | тело вращения и `inner_radius_ratio > 0.4`, то есть полое (труба, втулка) |

Ограничение: анализ идёт по вершинам. У грубых сеток (например, цилиндр из 16 граней) разброс будет
больше, а у моделей с крупными вырезами (шпоночный паз) он немного вырастет. Решение о 5D агент
принимает вместе с текстом задачи.

## 6. Полный анализ — `analyze`

Собирает всё вместе для инструмента `analyze_geometry`:

| Поле | Откуда |
|---|---|
| `triangles`, `size_mm`, `volume_cm3`, `surface_area_cm2` | базовые функции |
| `current_orientation` | `evaluate_orientation` для текущего положения |
| `mesh` | `mesh_topology` |
| `axisymmetry` | `axisymmetry` |
| `hints` | текстовые подсказки для агента (см. ниже) |

Правила для `hints`:

| Условие | Подсказка |
|---|---|
| есть открытые рёбра | сетка не замкнута — возможны дефекты слайсинга |
| `axisymmetric` | кандидат на 5D (и «похожа на трубу», если `hollow`) |
| высота > 3 × √(площадь основания) | высокая и узкая — риск опрокидывания, нужен brim или другая ориентация |
| контакт со столом < 25 мм² | маленькая площадь опоры |
| поддержки > 30 % объёма детали | много нависаний — стоит вызвать `suggest_orientations` |
| наименьший габарит < 2 мм | очень тонкое место — проверить ширину линии и число стенок |

## 7. Пороговые значения (где менять)

| Значение | Где | Смысл |
|---|---|---|
| `0.985`, `0.05 мм` | `evaluate_orientation` | грань «лежит на столе» |
| `0.1 мм` | `evaluate_orientation` | нижняя граница высоты нависания |
| `0.08` | `_candidate_directions` | шаг группировки нормалей |
| `14` | `_candidate_directions` | сколько крупных граней пробовать |
| `0.998` | `_candidate_directions` | порог «одинаковых» направлений |
| `0.2`, `0.3`, `0.5`, `25 мм²` | `_score` | веса рейтинга ориентаций |
| `8 × 24`, `75 %`, `0.06`, `0.4` | `axisymmetry` | разбиение, заполненность, порог тела вращения, порог полости |
| `400 000` | `mesh_topology` | предел числа треугольников для проверки сетки |

Если по тестовым моделям эталон жюри систематически выбирает другие ориентации, начинать стоит с
весов `_score`.
